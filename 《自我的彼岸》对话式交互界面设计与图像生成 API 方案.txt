《自我的彼岸》对话式交互界面设计与图像生成 API 方案
结合你们 Group 7 的项目提案、10.8–10.14 周报，以及你提供的 HiPro 对话式 UI/UX 设计教程，我建议把下一阶段的重点放在一个问题上：
如何让观众把模糊的理想、情绪和生活愿望，转化为自己能够确认的视觉意图，再让 AI 稳定地生成风格统一、语义准确、能够连续变化的动态图像？

这里的对话界面不应只是一个聊天框，而应该是一位温柔的视觉引导者：帮助观众表达、确认、修改和生成，同时保留观众对自己理想形象的选择权。

根据项目提案，《自我的彼岸》的核心体验是从真实镜像进入理想世界，经历 Perfect（完美）、Crack（裂隙）、Collapse（崩塌），最后重新回到真实的自己。周报中的 160 份有效问卷也表明，理想追求可能同时带来动力和压力，因此界面应避免把理想自我直接定义为优于现实自我的版本。

以下方案分为四部分：
1. 对话界面的交互设计 Draft。
2. 引导观众明确意图的对话策略。
3. 保持图像风格统一、语义准确和动态连续的生成系统。
4. 从 OpenAI API 到 VS Code 的设置与部署流程。

01 · Surface World｜表世界
真实镜像、呼吸、身体姿态、初始环境

02 · Conversational Guide｜对话引导
开放提问 → 语义提取 → 视觉选项 → 观众确认

03 · Intent & Style Engine｜意图与风格引擎
结构化意图、视觉规范、场景元素、生成约束

04 · Image & Motion Generation｜图像与动态生成
图像 API → 动态视频 API → 质量检查

05 · TouchDesigner｜沉浸式呈现
投影、镜像叠加、裂隙动画、最终回归真实

二、对话界面设计 Draft
https://chatgpt.com/c/6ad85871-1e54-83e8-8841-f2d64b0280fc
建议采用 Conversational UI + Visual Choice + Live Preview 的混合交互方式，而不是让观众填写一份很长的表单。

观众可以自然说话；系统将内容转化为简洁的视觉参数；界面通过可点击的选项帮助观众校准含义；只有在关键意图得到确认后，才开始生成正式画面

以项目提案中的艺术叙事为基础，沿用五个阶段：Observe（看见自己）→ Imagine（表达理想）→ Clarify（确认意图）→ Enter & Transform（进入与变化）→ Return（回到自己）。
设计目标不是让 AI 替观众定义什么是完美，而是引导观众把模糊的愿望表达出来，确认自己真正想看到的世界，再亲自决定何时进入、停留、改变或结束这段体验。

AI 主动说话： 温柔引导，控制体验节奏。
观众自由表达： 语音优先，文字输入作为备选。
界面提供选择： 当意图模糊时，用简单选项辅助表达，不要求观众懂 AI 或绘图术语。

第一阶段：Observe｜看见自己
体验目标：建立安全感，让观众从现实中的自己开始，而不是立刻进入自我优化模式。
第二阶段：Imagine｜表达理想
体验目标：让观众自由表达理想生活，收集其主动提出的人、事、物、情绪与愿望，不预设成功的定义。
第三阶段：Clarify｜确认意图
体验目标：让观众确认 AI 是否真正理解自己的愿望，并把抽象语言转化成可执行的视觉描述。
第四阶段：Enter & Transform｜进入与变化
这一阶段是作品的核心视觉叙事。建议拆成三个连续的视觉状态，而不是三轮彼此无关的生成任务。
第五阶段：Return｜回到自己
体验目标：让观众重新面对真实的自己，并保留对理想的开放态度，而不是强迫观众接受某个结论。

让观众明确意图的设计原则

最重要的是不要要求观众一次性写出完美 Prompt。应当让系统负责把自然语言整理成生成条件，再让观众修正理解偏差。

设计问题	                推荐方案	                应避免
观众不知道怎么描述	        开放问题 + 具体例子	      直接要求写完整 Prompt
同一句话存在多种含义	      展示系统理解，询问关键区别	直接猜测并生成
观众不懂视觉术语	          提供视觉参考和情绪选项	    让观众选择复杂的模型参数
生成结果偏离愿望	          提供局部修改与重新确认	    每次修改都从头生成
观众不想表达个人信息	      支持跳过、手动输入和清除会话	强迫语音输入或采集身份
理想世界产生压力	          让观众控制停留、变化和结束	把 AI 的解释当作观众的心理诊断

核心原则：AI 可以推断，但必须让观众有机会纠正推断。
对于诸如“我想要自由”这样的表达，系统不应直接把它转换为“豪宅、跑车、奢华生活”。它应该先识别出这是一种尚未完全明确的意图，再询问观众究竟在意的是空间、时间、经济条件还是情绪状态。

三、如何让 API 生成风格统一、输入准确的动态图像
这里需要区分三个目标：
- 语义准确：画面中出现观众真正想要的元素。
- 风格统一：颜色、光线、构图和材质在不同场景之间保持一致。
- 动态连续：图像变成视频后，主体、空间和镜头运动不会无故跳变。
它们不能单靠一个很长的 Prompt 解决，建议分别设计控制机制。

3.1 建立结构化意图，而不是直接使用原始语音

3.2 使用固定的 Style Bible：建议为《自我的彼岸》建立一份贯穿整个会话的视觉规范，简称 Style Bible。
    把 Style Bible 作为独立、版本化的配置文件，例如 style-bible.json，而不是让 LLM 每轮重新创作一套风格描述。
    同时要注意：同样的文字 Prompt 并不保证每次生成都具有完全一致的风格。 如需更强的一致性，可进一步使用参考图、图像编辑、固定的构图模板，以及经过测试的模型参数。随机种子（seed）也只有在具体模型和接口支持、且其他条件相近时才有参考价值。

搭建一个素材库，集中放置不同场景（根据前期调研，用户理想自我的存在场景：职场、生活、心态）以及不同风格的视频、短片素材，通过控制素材内容控制API生成质量和风格一致性。


3.3 用三层 Prompt 组合生成画面

LAYER 01 · STYLE LOCK 全局风格层
cinematic fine art, muted ivory and silver-gray palette, soft diffused light, spacious composition, consistent visual language


LAYER 02 · USER INTENT  用户意图层
oceanfront home, private creative studio, visible ocean, quiet independence, freedom to create


LAYER 03 · SCENE & MOTION  场景与动态层
wide establishing shot, slow camera push-in, subtle moving ocean reflections, stable architecture

3.4 让图像进入动态叙事
不建议把 Perfect、Crack、Collapse 三个阶段完全当成三个独立的文生图任务。否则人物、建筑、空间布局很容易发生变化，破坏叙事连续性。

更合适的流程是：
1. Perfect： 生成并确认一张核心场景图，建立空间和主体。
2. Crack： 在相同视觉基础上，通过图像编辑、叠加遮罩或实时视觉效果，逐渐加入细微裂纹、光线不稳定、反射错位。
3. Collapse： 让裂隙扩散，逐步降低亮度和不透明度，再过渡到真实镜面。
4. Return： 让系统回到摄像头的实时画面，而不是生成一张虚构的“现实中的观众”。
